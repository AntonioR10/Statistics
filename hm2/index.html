HMWK 2: From Wallet Seed to Ethereum Address

Analysis of the cryptographic pipeline, hierarchical derivation, primitives and historical context.

1. Historical Context & Timeline

  • 1977: RSA, the first widely adopted public-key cryptography.
  • 2001: Standardization of SHA-2 (including SHA-512) by NIST.
  • 2012: Introduction of BIP-32 (HD wallets) and the Keccak win in the competition for the SHA-3 standard.
  • 2013: Introduction of BIP-39 (mnemonic sentences).
  • 2014: Standardization of BIP-44 (multi-account paths).
  • 2015: Official standardization of SHA-3 (FIPS 202) and launch of the Ethereum network.
  • 2016: Introduction of EIP-55 (Ethereum mixed-case checksum addresses).

2. Role of Each Standard & Cryptographic Primitive

  • BIP-39 (2013): Encodes entropy as words that are easy to write down. It converts the entropy by appending a checksum computed with SHA-256, splitting the resulting block into 11-bit chunks mapped to a dictionary of 2048 words. The seed derived via PBKDF2 uses the optional passphrase as a "25th word".
  • BIP-32 (2012) & BIP-44 (2014): Handle hierarchical deterministic (HD wallet) derivation. From a single seed, an entire tree of keys can be derived using HMAC-SHA512. BIP-44 fixes the standard paths (for Ethereum coin_type = 60), ensuring interoperability between different wallets.
  • secp256k1: The elliptic curve y2 = x3 + 7 defined over a field of 2256 elements. It allows efficient computation of the public key Q = k · G via the double-and-add algorithm, making the inverse problem (ECDLP) intractable.
  • Keccak-256: A sponge-construction hash function. It compresses the 64 bytes of the public key into 20 bytes (160 bits) to form the address. Historical note: it differs from the NIST SHA3-256 standard because of a different padding and domain-separation convention.
  • EIP-55 (2016): A mixed-case (uppercase/lowercase) encoding mechanism based on the hash of the address. It serves to detect human typing errors without changing the actual value of the address or requiring changes to the base protocol.

3. Conceptual Distinctions

Key Generation Initial entropy

True randomness via a CSPRNG. The only non-deterministic step in the pipeline.

Key Derivation BIP-32 / BIP-44, PBKDF2

100% deterministic process: the same input always produces the same output. No new entropy is introduced.

Public-Key Crypto secp256k1

Asymmetric relationship k -> Q, easy forward, intractable in reverse. Enables digital signatures.

Hashing Keccak-256

Keyless, deterministic, fixed-length one-way function with a strong avalanche effect.

Checksums BIP-39, EIP-55

Lightweight systems for detecting human transcription errors; they offer no cryptographic security.

Encoding Mnemonic, Hex, Case

Changes the visual representation of data (string/binary format) without altering its informational content.

5. Statistical Properties & Test Vector

  • Entropy and Seed: If the entropy is uniform, the mnemonic phrase maps uniformly over the space of possibilities (2128 or 2256). The seed resulting from PBKDF2 is statistically indistinguishable from a random string.
  • Keccak Avalanche: Flipping a single input bit changes about 50% of the output bits. Over the 160 bits of an Ethereum address, roughly 80 bits are expected to change abruptly.
  • EIP-55 Robustness: The uppercase/lowercase pattern offers protection against random typing errors, with an estimated residual error probability of around 0.003% (2-15).
