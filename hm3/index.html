5. Discussion

Algorithm steps and role of the keys

ECC. The receiver keeps d secret (it decrypts) and publishes Q = d·G (it lets anyone encrypt). For each message the sender picks a fresh random k, computes C1 = k·G and the shared point S = k·Q = d·C1, then XORs each byte with a keystream byte derived from S and the position. Only someone who knows d (or k) can rebuild S. Caesar. One secret key shared by both sides: add it to each letter to encrypt, subtract it to decrypt.

Similarities and differences

Caesar Toy ECC
Type Symmetric, monoalphabetic substitution Asymmetric (public/private pair), randomised
Key space 26 Group order n − 1 (at most 17 here, d and d+n are equivalent). Real curves: about 2²⁵⁶
Statistics Letter frequencies preserved (index of coincidence stays near 0.066) Keystream varies per position and k varies per message, so bytes look flat
Attack Statistical (language model) Algebraic (solve d·G = Q)
Attack cost 26 candidates ≤ n by brute force, about √n with BSGS or Pollard rho; about 2¹²⁸ on a real curve

Effectiveness of the statistical attack

With enough letters the correct shift gives the best χ², bigram or trigram score. With very few letters the empirical frequencies are too noisy and the right key is not distinguishable, so success drops toward 1/26. The experiment above measures this. Bigrams use more information per letter than single-letter frequencies, so they usually need fewer letters. Exhaustive search needs a readability test, and counting common trigrams is the weakest one on short texts.

ECC attack and restricted key space

The attack solves the ECDLP: try d = 1, 2, … until d·G equals Q, then recompute S = d·C1 and decrypt. Unlike the Caesar attack it uses no knowledge of the language, only the group structure. It works because the search space is tiny. For a properly configured curve the order is about 2²⁵⁶, brute force needs roughly 10⁷⁷ steps and the best generic attacks still need about 2¹²⁸. Its security depends on the key space being large and the key being unpredictable, together with a sound curve and fresh random k.

Weaknesses from the design of the toy scheme

  • The group is so small that S can only take n − 1 values, so the ciphertext-only attack decrypts without ever finding d.
  • There is no authentication: flipping a ciphertext bit flips the same plaintext bit.
  • The keystream is a toy hash, not a secure KDF.

This is why the range 1…10000 asked for in the assignment is already capped here by n: restricting d adds nothing when the whole group has at most 17 elements.
